# Dataset

SeatWise does not depend on any external dataset. It ships with a **seeded, synthetic sample dataset** so the product can be demonstrated and tested end to end, plus **empty import templates** for real data.

## What is committed

| Path | Contents | Size |
|---|---|---|
| `data/sample/courses.csv` | 49 courses in 7 departments | 2.5 KB |
| `data/sample/candidates.csv` | 908 candidates with their courses | 82 KB |
| `data/sample/halls.csv` | 14 halls (rows x columns, blocked seats, accessible seats, aisles) | 0.7 KB |
| `data/sample/timetable.csv` | 6 sittings over 3 days, 49 course exams | 1.6 KB |
| `data/sample/seatwise_sample_workbook.xlsx` | All four sheets in one workbook, with a "How to fill" sheet | 55 KB |
| `data/templates/*_template.xlsx`, `*_template.csv` | Empty templates with one example row and a "How to fill" sheet | small |
| `data/templates/seatwise_import_template.xlsx` | Combined empty template | 10 KB |

The complete dataset is well under the 200 MB limit, so everything is committed; nothing needs downloading. The database `data/app.db` is created on first start and is not committed.

## Source and licence

- **Source:** generated by `scripts/generate_sample_data.py` (seed `2026`). No real person, organisation or record is involved: names are random combinations of common first and last names, and emails use the reserved `example.com` domain.
- **Licence:** produced by SeatWise itself; free to use, share and modify with the product.

## How it is generated

`scripts/generate_sample_data.py --seed 2026 --start 2026-10-12`

1. **Departments and courses.** Seven departments (ACF, SWE, DAN, MCD, ELS, BMG, HCA), each with seven courses:
   - `101`, `102`, `103` for the newer cohort
   - `201`, `202` for the second-year cohort
   - `203` and `204` as electives for the second-year cohort
2. **Shared paper.** `SWE-202` and `DAN-202` share one question paper (paper group `DB-COMMON`) and are examined in the same sitting. This exercises the subject-combination rule.
3. **Candidates.** Two cohorts per department of 55-75 candidates. Roll numbers are `<department><cohort><serial>` (for example `ACF24017`), with occasional gaps for withdrawn numbers. The second-year cohort picks one of two electives, so candidates of one department with neighbouring roll numbers write different papers in the same sitting, which exercises the roll-gap rule. About 1% need an accessible seat.
4. **Timetable.** Six sittings (morning 09:30-12:30 and afternoon 14:00-17:00 on three days). Every department has exactly one exam in every sitting, so each sitting has 7-9 papers and 397-511 candidates. No candidate has two exams in one sitting.
5. **Halls.** Fourteen halls in three buildings, from 6 x 6 to 10 x 12 seats, some with aisles and blocked seats. Four halls list their own accessible seats; the rest get the workspace default (2 front-row seats) at import.

The same seed always produces byte-identical CSV files; a different seed produces a different, equally valid dataset.

## Schema

These are the columns the importer accepts. Header spelling is flexible: for example `Roll No`, `roll_number` and `candidate_id` are all accepted for `roll_no`. Columns marked * are required.

### courses
| Column | Example | Notes |
|---|---|---|
| course_code* | ACF-201 | letters, digits, `- _ . /` |
| course_name* | Financial Reporting | |
| department_code* | ACF | |
| department_name | Accounting & Finance | needed the first time a department appears |

### candidates
| Column | Example | Notes |
|---|---|---|
| roll_no* | ACF24017 | unique; candidates use it to look up their seat |
| full_name* | Maya Fernandes | |
| department_code* | ACF | must exist |
| course_codes* | ACF-201;ACF-202;ACF-203 | separated by `;` (or `,` / `\|`) |
| needs_accessible_seat | no | yes / no |
| email | maya.fernandes@example.com | optional |
| date_of_birth | 2004-05-17 | YYYY-MM-DD (also DD/MM/YYYY) |

### halls
| Column | Example | Notes |
|---|---|---|
| hall_code* | MB-101 | |
| hall_name* | Room 101 | |
| building, floor | Main Building, 1 | |
| rows* | 8 | 1-26 (rows are lettered A-Z from the front) |
| columns* | 8 | 1-30 |
| blocked_seats | D4;D5 | seats that cannot be used |
| accessible_seats | A1;A2 | empty = workspace default |
| aisles_after_columns | 4 | an aisle after these column numbers |

### timetable
| Column | Example | Notes |

| course_code* | ACF-201 | each course once |
| paper_group | DB-COMMON | courses sharing one question paper, in the same sitting |

## Cleaning and validation

There is nothing to clean in the synthetic data. Real uploads are validated row by row before anything is saved: required columns, formats, duplicates, unknown departments or courses, seat labels outside the layout, blocked-and-accessible conflicts, aisle positions, time order, split paper groups, timetable clashes (a candidate in two papers of one sitting), and sitting sizes above total capacity (warning). See [07_USER_GUIDE.md](07_USER_GUIDE.md#import-data).

## Engine benchmark scenarios

The benchmark uses its own seeded scenarios generated in memory by `ml/scenarios.py` (150 to 2,000 candidates; see [05_MODELS_AND_TRAINING.md](05_MODELS_AND_TRAINING.md)). They are rebuilt identically from their seeds, so they are not stored as files.

## Download guide

Not needed: there is no external or Kaggle dataset and no API token is required. To regenerate the sample files:

```bat
venv\Scripts\python scripts\generate_sample_data.py            :: the committed data (seed 2026)
venv\Scripts\python scripts\generate_sample_data.py --seed 7   :: another dataset
```
