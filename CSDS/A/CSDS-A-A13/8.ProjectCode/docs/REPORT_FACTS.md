## 2. What the product is (and is not)

- A web application: React 18 + TypeScript + Vite frontend, FastAPI + SQLAlchemy 2 + SQLite backend.
- The core is an **optimisation engine (Google OR-Tools CP-SAT)**, not a trained model. **No model is trained**, so there is no train/validation/test split, no accuracy/F1, no confusion matrix. The honest "evaluation" is an engine **benchmark** against manual seating methods (sequential roll order, round-robin interleave, random shuffle).
- The title says "AI-enabled": the AI component is constraint programming / combinatorial optimisation with seeded randomisation (classical AI), not machine learning. Documents must say this plainly.
- Everything runs offline; no API keys.

## 3. Engine design facts

- Two stages. **Stage A** (CP-SAT, 2 passes): decides, per hall, how many candidates of each (paper, department, accessible-need) group go there and which **colour class** of the hall's seat graph each paper uses. 8-neighbour adjacency -> 4 colour classes by (row parity, column parity); 4-neighbour -> 2 classes (chessboard). A paper confined to one class per hall can never sit next to itself, so same-paper neighbours are impossible by construction. Pass 1 minimises peak fill and spreads papers/departments; pass 2 keeps that optimum and maximises a seeded random weight (weights 0-999).
- **Stage B** (CP-SAT, per hall, in parallel threads, 1 deterministic worker each): Boolean x[candidate, seat]; exactly one seat per candidate, at most one candidate per seat, accessible-need candidates only on accessible seats; roll-number gap enforced by at-most-one clauses; objective: minimise same-department neighbour pairs (weight = candidates x 20 + 1) minus a seeded random term (weights 0-19).
- Halls solved in parallel; a hall that finds nothing in budget gets 4x budget once; otherwise Stage A re-balances (max 5 retries).
- **Independent validator** (plain Python, no solver) re-checks every rule and produces the scorecard.
- Seeds: every sub-seed derived by SHA-256 from the plan seed. Stored per plan: `data_fingerprint`, `solver_hash`, `assignment_hash` (SHA-256). **Verify** re-runs the engine and compares hashes.
- Settings: per-hall deterministic budget 0.15 (tuned), Stage A budget 0.3, engine version 1.0.0, OR-Tools 9.15.6755.
- Pre-checks give plain-language reasons (seats, accessible seats, dominant paper ceiling = largest colour class summed over halls).
- Default rules: adjacency 8, roll gap 5 (same prefix), department mix on, fill strategy compact, accessible seats per hall 2 (default when a hall lists none).
- Manual swap checker applies the same rules (`services/swap.py`); illegal moves return 409 with reasons.

## 8. Honest gaps (state plainly in the documents)

1. No machine-learning model: nothing is trained; no accuracy / F1 / confusion matrix exist. Evaluation is a benchmark of an optimisation engine.
2. All data is synthetic. No real examination-office data and no pilot with real invigilators or candidates; **no user-acceptance testing with real users was performed**.
3. The base paper reports **no quantitative results** (only a stated requirement: 100 students in under 3 s) and uses different data, so a numeric head-to-head comparison is impossible. The benchmark's round-robin method is the closest proxy for the base paper's interleaving ("zipper") idea; it is not a re-implementation of the base paper.
4. Benchmarks were run on one 12-thread desktop; no other hardware tested. RAM, CPU load and concurrent-user load were not measured. No load or penetration testing.
5. The frontend has no automated component/E2E test suite; it is checked by the TypeScript strict type check, the production build and manual browser walkthroughs (as recorded in docs/09_TESTING.md). Backend tests: 58.
6. The front-row bias of SeatWise (4.7 pp) is higher than random shuffle (1.6 pp) - a known trade-off of the colour-class construction.
7. 4-neighbour mode is slower (6.0 s vs 2.4 s at 600 candidates).
8. Single-machine SQLite deployment; no cloud, SMS/e-mail or face-recognition features (future scope).
9. A paper larger than the sum of colour-class ceilings across the selected halls cannot be seated (the engine explains this rather than breaking a rule).
10. Student 4's roll number, the guide name, college name, HOD and principal are not in the batch files.
