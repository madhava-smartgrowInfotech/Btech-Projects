# HubLocator

**Advanced Optimization in E-Commerce Logistics: Combining Matheuristics With Random Forests for Hub Location Efficiency**

Batch A4 · CSE (Data Science), Section A · Base paper: IEEE Access 2025, DOI 10.1109/access.2025.3550560

A pure-Python, end-to-end implementation of the predict-then-optimise framework adopted from the base paper:

```
historical orders ──► Random Forest ──► regional demand forecast ──► hub location MIP ──► matheuristic ──► hubs + allocation
       ▲                                                                                                          │
       └──────────────────────────── new month of data: re-forecast and re-optimise ◄─────────────────────────────┘
```

## Quick start

```bash
pip install -r requirements.txt
python run.py forecast       # train the Random Forest demand model  (~10 s)
python run.py serve          # web interface at http://127.0.0.1:5000
```

A trained forecaster and pre-computed results are already included, so `serve` works immediately.

Other commands:

```bash
python run.py optimize --period 2025-10 --hubs 6      # plan hubs for a month, scored on realised demand
python run.py optimize --exact                        # same with the traditional exact MIP
python run.py compare --period 2025-10                # proposed vs traditional methods
python run.py rolling --months 6                      # month-by-month re-optimisation vs static plan
python run.py benchmark --factors 1 2 3               # scalability: exact MIP vs matheuristic
python run.py data --seed 7                           # regenerate the synthetic history
python run.py all                                     # data -> forecast -> compare -> rolling
python tests.py                                       # smoke tests
```

## How each project objective is implemented

| Objective | Where |
|---|---|
| 1. Collect & preprocess historical logistics data | `hublocator/data.py` — 90 demand regions (30 Indian cities + satellite districts), 36 months of orders with growth, festival peaks, promotions; cleaning, de-duplication, gap interpolation. Replace `data/*.csv` with real data of the same schema. |
| 2. Predict regional demand with Random Forest | `hublocator/forecast.py` — lag, rolling, seasonal, promo and region features; time-based hold-out; compared with naive forecasters |
| 3. Formulate hub location with cost, time, capacity constraints | `hublocator/model.py` — capacitated single-allocation hub location MIP (fixed cost + transport + delivery-time penalty, capacity, p-hub limit, optional hard SLA) built with PuLP |
| 4. Solve efficiently with a matheuristic | `hublocator/matheuristic.py` — greedy/k-medoids construction → MIP-priced local search (swap/add/drop, screened by a cheap greedy bound) → kernel search (restricted exact MIP) |
| 5. Re-optimise as demand changes | `hublocator/rolling.py` — rolling horizon: re-forecast with data available at that time, re-plan, score on realised demand, track hub openings/closings; compared with a static fixed-demand plan |
| 6. Compare with traditional methods | `hublocator/baselines.py` — exact MIP (time-limited), greedy heuristic, k-means clustering, "largest markets" rule, historical-average (fixed) demand; metrics: delivery time, fulfilment rate, SLA reliability, operating cost |

## Results (included in `models/` and `results/`)

**Demand forecast** (6 held-out months, 90 regions)

| Forecaster | MAE | RMSE | MAPE | R² |
|---|---|---|---|---|
| Random Forest (proposed) | 1,970 | 6,479 | 7.7 % | 0.978 |
| Last month's value | 4,151 | 12,604 | 19.7 % | 0.915 |
| 3-month moving average | 3,786 | 11,882 | 17.6 % | 0.925 |

**Method comparison** — planned for Oct 2025 (festival peak), scored on realised demand, p = 6

| Method | Operating cost | vs proposed | Avg delivery | Fulfilment | Solve time |
|---|---|---|---|---|---|
| RF forecast + matheuristic (proposed) | ₹62.2 M | — | 8.6 h | 92.4 % | 3.5 s |
| RF forecast + exact MIP | ₹62.2 M | 0.0 % | 8.6 h | 92.4 % | 12.8 s |
| RF forecast + greedy heuristic | ₹69.2 M | +11.3 % | 9.5 h | 89.4 % | 0.01 s |
| RF forecast + k-means clustering | ₹64.3 M | +3.4 % | 9.2 h | 91.9 % | 0.03 s |
| Largest-markets rule | ₹72.5 M | +16.7 % | 9.0 h | 91.3 % | 0.0 s |
| Historical-average demand + matheuristic | ₹67.2 M | +8.1 % | 9.9 h | 66.0 % | 4.5 s |

**Rolling re-optimisation** (Jul–Dec 2025): adaptive plan 98.3 % avg fulfilment vs 83.7 % for a static plan, at 4.9 % lower operating cost.

**Scalability** (exact MIP with a 40 s limit): 90 nodes — matheuristic 3 s / exact 13 s (both optimal); 180 nodes — 8 s / 43 s; 270 nodes (73k binary variables) — matheuristic 31 s, exact MIP not solved in 67 s.

All numbers are regenerated by the commands above and shown in the web interface.

## Web interface

- **Dashboard** — dataset overview, monthly volume chart, pipeline status, latest comparison
- **Forecast** — RF vs baselines, feature importance, next-month forecast per region, back-test chart
- **Plan hubs** — choose month and parameters (p, capacity factor, costs, SLA, hard/soft, matheuristic or exact), see KPIs, network map, hub utilisation, allocation and the search log
- **Compare methods** — run the comparison and the scalability benchmark (background jobs, page auto-refreshes)
- **Re-optimise** — rolling-horizon results, adaptive vs static fulfilment by month, hub changes

JSON API: `GET /api/forecast`, `POST /api/optimize {"n_hubs":6,"period":"2025-10",...}`, `GET /api/compare`, `GET /api/rolling`.

## Notes

- Everything runs offline. PuLP's bundled CBC solver handles the MIPs; if PuLP is missing the app falls back to greedy allocation (the exact-MIP baseline is then skipped).
- Model economics (transport rate, fixed hub cost, time penalty, SLA, capacity factor) are in `hublocator/config.py` and adjustable on the *Plan hubs* page.
