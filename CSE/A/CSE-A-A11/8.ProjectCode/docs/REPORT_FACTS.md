## 2. What the system is (as built)
Two front doors on one Python engine (`autosecai/`, 2881 non-blank lines in 14 modules):
1. **PR review** - ingest a unified diff / before-after file / GitHub PR URL / uploaded files, zip or folder; run **7 agents**
   (Ingestion, Static Analysis, ML Risk, Security Reasoner, Remediation, Quality Reviewer, Judge); produce a risk score 0-100, a verdict
   (APPROVE / REQUEST_CHANGES / BLOCK), findings with CWE / OWASP mapping, explanation, impact, exploit sketch, remediation, safe pattern,
   and a **verified auto-patch** (the patch is re-scanned after application). Exports: Markdown PR comment, SARIF 2.1.0, JSON, CSV, patched files.
2. **Codebase assistant** - index a repository (demo shop, this project, zip, local folder, GitHub URL); TF-IDF + concept scores + import/call graph
   (personalised PageRank) retrieval; answers with evidence chunks and "why" chips; repository map and onboarding guide.
3. **Model Lab** - reproduction of the base-paper pipeline on Python: 14 AST metrics, 7 feature selectors, SMOTE-Tomek, 9 classifiers, vulnerability-type classifier, ablation, "try it" scoring.
- LLM mode is **optional and off by default** (Anthropic key in Settings). Without it nothing leaves the machine. **LLM mode was not measured** (no key during the build) - state as a gap.
- Languages: deep AST + taint analysis for **Python**; regex rules for JavaScript, PHP and Java (JS_INNERHTML, JS_EVAL, JS_EXEC, PHP_SQLI, PHP_INCLUDE, JAVA_SQLI, GENERIC_SECRET).
- Rule knowledge base: **43 rule entries** = 30 static security rules + 12 quality rules + 1 ML-derived (Q_ML_RISK). Each carries CWE, OWASP category, severity, explanation, impact, remediation, safe pattern.
- The product originally had **no HTTP API and no login**: a thin FastAPI layer (`backend/`, 502 lines) and SQLite/bcrypt/JWT accounts were added; a React 19 + TypeScript + Tailwind 4 frontend (kit V1 "Aurora Glass", 69 source files, 6525 non-blank lines) replaces the Streamlit UI (613 lines, still present and untouched, not runnable on this machine: Streamlit and Plotly not installed).

## 3. Architecture summary
- Browser (React SPA, port **5311**) -> Vite dev proxy `/api` -> FastAPI (port **8311**) -> `autosecai` engine -> SQLite.
- Long operations (review, retrain) run as **background jobs** in an in-memory `JOBS` dict + threads; the UI polls `GET /api/jobs/{id}` and shows the agents' live messages.
- Auth: bcrypt (rounds 10) password hashes, HS256 JWT (12 h), key = sha256(`JWT_SECRET`). Demo account `demo@autosecai.dev` / `Demo@1234` seeded at start-up.
- Persistence: `data/app.db` (table `users`: id, email UNIQUE, name, password_hash BLOB, created) and `data/history.db` (table `reviews`: id PK, created, title, source, score INTEGER, verdict, n_findings, n_security, payload JSON).
- Trained artefacts: `autosecai/artifacts/` (`bundle.joblib`, `report.json`, `dataset_metrics.csv`, `dataset_samples.csv`).
- Pipeline order and responsibilities of the 7 agents: see `autosecai/agents.py` docstring (ingestion -> static -> ML risk -> reasoner -> remediation -> quality -> judge).
  Judge scoring: per-finding weight = severity weight (critical 10 / high 6 / medium 3 / low 1 / info 0.2) x confidence weight (high 1.0 / medium 0.7 / low 0.4); findings outside the changed lines count 15 %; info-level quality findings are skipped;
  **risk score = round(100 x (1 - exp(-total weight / 18)))**. Verdict: **BLOCK** if any in-diff security finding is high/critical with medium+ confidence or score >= 70; **REQUEST_CHANGES** if any in-diff medium+ finding or score >= 30; else **APPROVE**.

## 5. Dataset (honest statement)
- **The ML corpus is generated, not real.** `autosecai/dataset.py` generates 6,000 Python functions (seed 7): random benign filler logic + injected vulnerable patterns
  (8 types) + look-alike safe patterns (hard negatives) + 1 % label noise. Metrics are then measured on the real generated source with the AST metric extractor.
- Source of the *idea*: the base paper uses **21,759 C/C++ functions from 10 open-source projects, only 275 vulnerable (1.26 %)**, labelled from CVE/NVD (SQLite, FreeType, LibTIFF, Libxslt, Binutils, FFmpeg, ImageMagick, OpenSC, rdesktop, plus OpenSSL per the abstract). Those datasets are C/C++ and not bundled.
- Licence: the generated corpus is the project's own output (no third-party data, no licence constraint). Not published beyond `dataset_metrics.csv` / `dataset_samples.csv` in the repository.
- Size: 6,000 functions, 501 vulnerable (8.35 %). Split 75 / 25 stratified, `random_state=42`: train 4,500 / test 1,500.
  After SMOTE (k=5) + Tomek-link removal the balanced training set has 8,232 rows (16 Tomek removals). Test set is untouched (125 vulnerable / 1,375 safe).

### 5a. The 14 metrics (M1-M14, Python-AST analogues of the paper's code-property-graph metrics)
M1 cyclomatic complexity, M2 lines of code, M3 local variables, M4 call sites, M5 parameters, M6 index arithmetic, M7 variables in index arithmetic, M8 I/O and query calls, M9 nested control structures, M10 loops, M11 max control dependency, M12 risky API calls, M13 string-built sinks, M14 untrusted/sensitive sources.
M1-M11 mirror the paper's families; **M12-M14 were added by this project** (taint-oriented, needed because Python injection flaws are not memory flaws).

- **Caveat:** the corpus generator and the rules were written by the same team around the same eight patterns, so the rule-engine numbers are optimistic for real code. About 1 % label noise means some "positives" contain no vulnerable code, which no detector can find.

## 12. Known limitations (use in Scope and Limitations)
1. ML model trained on a **generated** Python corpus; scores are a prioritisation signal, not evidence of exploitability.
2. Deep analysis is **Python-only**; JS/PHP/Java are regex rules.
3. Whole-file auto-fixes exist only when a full file (not a bare diff hunk) is supplied.
4. No labelled real-PR benchmark; precision on real PRs unknown. No comparison against Bandit / Semgrep / CodeQL was run.
5. LLM mode optional and unmeasured; the "multi-agent" pipeline is deterministic software agents, with an optional LLM text layer.
6. Single machine, in-memory job table (lost on restart), SQLite, no rate limiting beyond bcrypt cost. Review history is shared by all accounts (the reviews table has no user id).
7. Streamlit UI not runnable here (dependencies not installed); new React UI is the verified front end.
8. Stored `bundle.joblib` loads with a scikit-learn / XGBoost version-persistence warning on this machine; scores unaffected in tests.
