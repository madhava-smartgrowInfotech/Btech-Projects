# CipherVeil - how it works

## Send

1. Read the file; build a small header `{name, size, sha256}`.
2. Generate a fresh 256-bit AES session key and a 96-bit random nonce.
3. Encrypt `header_len | header | file` with AES-256-GCM (additional data = magic `CVL1`).
4. Wrap the session key with the receiver's RSA public key using OAEP (SHA-256, MGF1-SHA-256).
5. Bundle: `CVL1 | wrapped_key_len(2) | wrapped_key | nonce(12) | ciphertext+tag`.
6. Check capacity: the cover holds `(width x height x 3 - 32) / 8` bytes.
7. Write `length(32 bits) | bundle` into the lowest bit of each R, G, B value, row by row from the top-left pixel. Save as PNG.
8. Measure PSNR, SSIM and timings against the untouched cover.

## Receive

1. Read the length header and the bundle bits from the image LSBs; reject images without a plausible header.
2. Check the magic and the wrapped-key length, unwrap the session key with the private key.
3. AES-GCM decrypt: a wrong key, flipped bit or truncated bundle fails the tag check and nothing is released.
4. Compare the SHA-256 recorded inside the encrypted header with the hash of the restored file.

## Key exchange

The receiver generates an RSA keypair (2048, 3072 or 4096 bits), exports the **public** PEM and gives it to the sender, who imports it as a public-only entry. A fresh AES key per message means that one compromised message key never exposes another message.

## Measurements

- **PSNR** `10 log10(255^2 / MSE)` over all RGB values; above 50 dB is considered imperceptible. With a 1-bit LSB the theoretical floor is about 51 dB (every bit changed half the time).
- **SSIM** per colour channel (scikit-image, data range 255), averaged.
- **Capacity** in bytes and bits per pixel (maximum 3.0).
- **Robustness**: for each attack the stego image is modified, extraction and decryption are attempted with the real private key, and the recovered file hash is compared with the original. The LSB error rate compares the first bundle-length bits of the LSB stream before and after.

## Data and sources

No dataset is used. Everything is committed and regenerated by the seeded script `scripts/make_samples.py`.

| Item | Source | Licence | Committed |
|---|---|---|---|
| `astronaut_512x512.png` | scikit-image `data.astronaut()`, a NASA photograph | Public domain | yes |
| `coffee_600x400.png`, `coffee_small_200x200.png` | scikit-image `data.coffee()` (crop and resize for the small one) | CC0 | yes |
| `cat_451x300.png` | scikit-image `data.chelsea()` | CC0 | yes |
| `rocket_640x427.png` | scikit-image `data.rocket()` | Public domain | yes |
| `generated_landscape_1280x720.png` | Procedurally generated, seed 11 | Generated here | yes |
| `data/payloads/*` | Synthetic memo (PDF), CSV, text and JSON files generated here | Generated here | yes |

Any image or file you upload at run time can be used instead (up to 25 MB).

## Layout

```
backend/app/services/   crypto.py lsb.py metrics.py plots.py robustness.py benchmark.py pipeline.py
backend/app/routes/     auth keys samples ops analysis (robustness, benchmark, log)
frontend/src/pages/     Landing Login Keys Send Receive Analysis Robustness Log
ml/eval.py              evaluation -> experiments/eval/metrics.json and summary.md
scripts/                smoke_test.py make_samples.py
```

## Database

SQLite at `data/app.db`: `users` (bcrypt hashes), `keypairs` (PEMs; `private_pem` is empty for public-only entries) and `oplog` (operation, status, JSON details with sizes, timings, metrics and key fingerprints only).
