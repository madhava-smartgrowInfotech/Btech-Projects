## 2. What the system does

Send: file -> header `{name,size,sha256}` -> AES-256-GCM (fresh 256-bit key, fresh 96-bit nonce, AAD = magic `CVL1`) -> session key wrapped with the receiver's RSA public key (OAEP, SHA-256, MGF1-SHA-256) -> bundle `CVL1 | wrapped_key_len(2) | wrapped_key | nonce(12) | ciphertext+tag` -> capacity check -> 32-bit length + bundle written into the LSB of each R, G, B value row by row -> PNG.
Receive: read length header and bits -> check magic and wrapped-key length -> RSA unwrap -> AES-GCM decrypt (tag check) -> compare the SHA-256 stored in the header with the hash of the restored file.
Capacity: `(width x height x 3 - 32) / 8` bytes = 3.0 bits per pixel. Bundle overhead: 401 B (RSA-2048), 529 B (RSA-3072), 657 B (RSA-4096) for a short file name (wrapped key + magic 4 + length 2 + nonce 12 + header length 2 + header JSON + tag 16).
Measures: PSNR `10 log10(255^2/MSE)` over all RGB values (scikit-image), SSIM per channel averaged (data range 255), MSE, largest change, values changed, capacity used, per-stage timings.
Nine robustness attacks in the app: lossless PNG re-save, JPEG q95/75/50, Gaussian noise sigma 1/3, resize 90 %, crop bottom 10 %, crop left 10 %; each ends with a real decrypt attempt and a hash comparison.

### D. Steganalysis (honest limit of plain sequential LSB)

- Chi-square (Westfeld-Pfitzmann) on the known embedded prefix: stego p-value above 0.5 in **30 of 30** cases (p = 0.97-1.00); the unmodified cover prefix gave p < 0.5 in 27 of them. In 3 cases (cat 10/25 % and coffee_small 10 %) the clean cover prefix already looked equalised (p 0.58-0.999), so the test does not separate the two there. This is an oracle test (it knows how many values were used).
- Weighted-stego (blind, whole image): the estimated embedded fraction tracks the true fraction (0.10 -> 0.10-0.30, 0.50 -> 0.49-0.62, 1.00 -> 0.99-1.03); on clean covers it returns 0.08-0.18 for 4 of 6 images (natural-image bias) and about 0 for two. At 1 % fill and below nothing was tested.
- Conclusion to state: CipherVeil hides the bundle from the eye (PSNR above 50 dB) and from simple inspection, but does not resist a statistical steganalysis tool at medium and high fill; embedding is sequential from the first pixel and independent of any key. Low fill ratios are safer, not safe.

## 10. Comparison with the base paper and the supporting papers (state plainly: different goals and data)

- **ProSt** (base paper, IEEE Access 2026): hides secret bits among random decoy LSBs at a secret position and lets an untrusted cloud compute on them with Fredkin gates; security is an adversary advantage of order 1/n (Theorem 1, written Theta(1/n)) in the number n of LSB positions, so n >= 2^20 (about 10^6) is recommended for an advantage below 10^-6; it does not report PSNR, SSIM or capacity. Runtime reported: 8.38 s for a 17-gate, 61-wire circuit on a 128x128x3 image (i5-1135G7, 16 GB, Windows 11). CipherVeil moves a whole file from sender to receiver instead; its numbers are not like-for-like with that runtime. It adopts the LSB carrier idea and key-exchange framing, and adds AES-GCM + RSA-OAEP and imperceptibility, capacity and robustness measurements. It does not implement homomorphic computation, decoy-bit location hiding or a provable security argument.
- **SCReedSolo** (arXiv:2503.12368, supporting): random shuffling + Fernet + Reed-Solomon + LSB, 3 bpp; reported PSNR 51.774 dB / SSIM 0.996 (5.46 M-character text into a 14589x8423x3 image), 57.653 dB / 0.936 (audio into 21188x30328x3), 52.888 dB / 0.996 (100x100x3 image into 512x512 Lenna). Different covers and payloads; CipherVeil's 52.5-74.6 dB (up to 73 % fill) and 51.1-51.2 dB at 100 % fill are the same order. It adds error correction and shuffling; CipherVeil has neither, and recovers nothing after JPEG, noise or resizing.
- **Memristive lightweight encryption** (arXiv:2605.03494, supporting): IMPLY-logic Trivium and Grain-128a for in-memory steganography; energy/step reductions up to 42 % and 44 %; hardware-level work, no software comparison possible.

## 13. Known limits to state in the documents

1. LSB data survives only lossless handling; one JPEG pass, any noise, resize, rotation, flip or colour reduction destroys it. No error correction.
2. Sequential, key-independent embedding: chi-square and weighted-stego analysis detect medium and high fill; no adaptive (edge) embedding, no key-driven permutation.
3. Private keys sit unencrypted in the local SQLite database; the JWT secret ships as a placeholder; no login rate limit.
4. RSA only (no ECC, no hybrid post-quantum); no sender authentication or signatures: anyone with the public key can send, the receiver cannot tell who.
5. Image carriers only (PNG, RGB, alpha dropped); 25 MB upload cap; no audio or video.
6. Six committed cover images and four small synthetic payloads; no camera photographs or large corpus; single machine, single run conditions.
7. No steganalysis resistance proof; the base paper's provable-security and homomorphic-computation ideas are out of scope.
8. Frontend defect: Send page crashes for an account with zero keys (missing `KeyRound` import).
