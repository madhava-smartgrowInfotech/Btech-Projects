## 2. Architecture and code

- Python 3.11.9, FastAPI 0.110 (requirements pin) with uvicorn, `cryptography` 42.0.7, XGBoost 2.0.3, scikit-learn 1.5.0, PyTorch (requirements pin 2.2.0; 2.14.1+cpu on the machine used for measurement), pandas 2.2.1, numpy 1.26.4. Front end: React 19 + Vite 8 + Tailwind 4 + Recharts + three.js ('Kinetic Mono' V5 kit); legacy dashboard in `web/` (plain HTML/JS).
- Modules: `cipherguard/crypto/secure_channel.py` (160 lines: KeyPair, SecureChannel: derive_session_key, encrypt, decrypt, encrypt_with_ephemeral); `cipherguard/ids/` features.py (42-feature schema), preprocessing.py (ColumnTransformer: MinMaxScaler on 39 numeric + OneHotEncoder on proto/service/state), synthetic.py (generator), train.py (XGBoost + CNN + LR stacking), inference.py (ThreatSenseEngine); `cipherguard/api/main.py` (382 lines).
- Model: XGBoost (200 trees, depth 6, lr 0.08, subsample/colsample 0.85, scale_pos_weight = neg/pos) + 1D CNN (Conv1d 1->32 k3, MaxPool2, Conv1d 32->64 k3, MaxPool2, Linear->64, Dropout 0.3, Linear->1, sigmoid; Adam 1e-3, batch 256, <=15 epochs, early stopping patience 5; **plain BCE loss - class weighting exists only in the TensorFlow branch, which was not used**) + Logistic Regression meta-model fitted on the validation split's [p_xgb, p_cnn]. Decision threshold 0.5. Severity bands on stacked probability: >=0.85 critical, >=0.70 high, else medium (normal = low).
- Encoded input: 70 dims for the synthetic bundle (39 numeric + 31 one-hot), 192 dims for real UNSW-NB15 (more proto/service/state values).
- Crypto flow: sender makes an ephemeral P-256 key pair, ECDH with the cloud's long-term public key, HKDF-SHA256 (info `cipherguard-shield-v1`, no salt) -> 32-byte AES key, AES-256-GCM with 12-byte random nonce; tag (16 B) stored separately; wire envelope = ciphertext (same length as plaintext) + 12 B nonce + 16 B tag + 65 B uncompressed ephemeral public key = **93 bytes fixed overhead**. The 'cloud' is an in-process mock with a process-lifetime key pair; the API also caches session keys by ephemeral key (demo shortcut) and falls back to real ECDH with the cloud private key when the cache is empty (tested).
- **No database.** Alerts are an in-memory list capped at 500 (lost on restart); model/report artefacts are files. The ER diagram therefore shows logical entities, not tables.
- Limits enforced: text <=1 MB, file <=5 MB, CSV <=10 MB and <=10,000 rows; non-CSV, empty, malformed base64, missing ephemeral key and tag mismatch return 400; engine missing -> 503. CORS `*`, no authentication, no TLS in the demo.
- Lines of code: cipherguard 1,464 (api 382, crypto 163, ids 919, incl. __init__ files), scripts (original) 247, tests 250, web legacy 566 (html 166, js 260, css 140), React console source 3,210 lines (pages, components, libs). Added in this documentation run: scripts/run_experiments.py, benchmark_crypto.py, measure_pipeline.py, make_real_bundle.py, fetch_unsw_nb15.py, capture_real_screens.py, serve.py, tests/*.

## 3. Data

- **Shipped model (what the app runs by default):** trained on a **synthetic** 12,000-row dataset (6,000 normal + 6,000 attack) generated by `cipherguard/ids/synthetic.py` with the UNSW-NB15 *schema* (42 features) - not real traffic. Split stratified 70/15/15 = 8,400 / 1,800 / 1,800 (seed 42). 2.5 % label noise (300 flipped rows) is injected, so accuracy cannot exceed about 0.975 if the clean classes were separable; `attack_cat` of attack rows is drawn with an unseeded `np.random.choice` (not reproducible).
- **Real data used for the experiments:** UNSW-NB15 (Moustafa & Slay, UNSW Canberra Cyber Range Lab, 2015). Official partition: training set 175,341 flows (56,000 normal / 119,341 attack), testing set 82,332 flows (37,000 normal / 45,332 attack = 55.06 % attack). Obtained via the Hugging Face repackaging `lacg030175/UNSW-NB15` (config `standard`, CC-BY-4.0 packaging; original data free for academic use with citation). Same 42 features as the app. Attack categories: Normal, Generic, Exploits, Fuzzers, DoS, Reconnaissance, Analysis, Backdoor, Shellcode, Worms.
- Train/test of the official partition are **temporally separated** (different capture periods), which is harder than a random split.
- Base paper's data: 9,000 balanced samples (4,500 per class) of UNSW-NB15, stratified 70/15/15, 10 repetitions, averages reported.

## 5. Cryptography and latency (experiments/crypto, experiments/pipeline)

Machine: Intel Core i5-12500 (6 cores / 12 threads), 15.7 GB RAM, Windows 11, Python 3.11.9, cryptography 42.0.7. Medians over repeated runs (reps in JSON); the machine was shared with other jobs, so treat absolute values as indicative.

| Payload | SecureChannel enc (ms) | SecureChannel dec (ms) | AES-256-GCM only enc / dec (ms) | RSA-2048-OAEP+AES enc / dec (ms) | RSA-3072-OAEP+AES enc / dec (ms) |
|---|---|---|---|---|---|
| 1 KB | 0.122 | 0.104 | 0.008 / 0.008 | 0.029 / 0.449 | 0.044 / 1.351 |
| 10 KB | 0.145 | 0.116 | 0.009 / 0.009 | 0.032 / 0.443 | 0.046 / 1.458 |
| 100 KB | 0.510 | 0.302 | 0.026 / 0.026 | 0.050 / 0.471 | 0.065 / 1.442 |
| 1 MB | 4.263 | 2.990 | 0.787 / 0.797 | 0.811 / 1.230 | 0.970 / 2.236 |
| 5 MB | 21.387 | 14.213 | 3.895 / 3.327 | 3.774 / 3.695 | 3.806 / 4.699 |

SecureChannel timings include the ephemeral key generation, ECDH, HKDF and **base64 encoding/decoding of the payload** (the API returns base64), which is why large payloads cost more than raw AES-GCM (AES-GCM alone ~1.3 GB/s at 1-5 MB; SecureChannel ~235 MB/s). ECDH P-256 key generation 24 us; ECDH + HKDF 53 us; RSA-2048 key generation 68 ms and RSA-3072 104 ms (one-time, single sample). RSA decrypt (key unwrap) costs 0.45 ms (2048) / 1.4 ms (3072) per message versus 0.05 ms for the ECDH + HKDF step; RSA encrypt is cheaper (0.03-0.04 ms) because the public exponent is small. Wrapped-key size 256 B (RSA-2048) vs 65 B ephemeral point (P-256).
Tamper tests (1,000 trials each): untouched accepted 1000/1000; ciphertext bit flip rejected 1000/1000; tag bit flip 1000/1000; nonce bit flip 1000/1000; ciphertext truncated by one byte 1000/1000; decryption with another party's key 1000/1000. 20,000 encryptions of one plaintext gave 20,000 distinct nonces and 20,000 distinct ciphertexts.

In-process protected transfer of a 100 KB payload (score 1 flow + encrypt + decrypt), median: IDS scoring 3.92 ms, encrypt 0.54 ms, decrypt 0.38 ms, total 5.67 ms (p95 7.35); IDS share of the total 81 %, encryption 11 %, decryption 8 %. Batch scoring: 120 rows 5.7 ms, 1,000 rows 16.6 ms. Engine load 112 ms.
HTTP API on 127.0.0.1 (median / p95 ms): health 0.78 / 1.15; score_single 5.47 / 6.01; encrypt_1kb_text 1.20 / 1.38; decrypt_1kb_text 0.91 / 1.09; encrypt_file_1mb 17.23 / 38.54; score_batch_120_rows 19.02 / 19.68; protected_transfer_via_api_1kb 8.11 / 8.86.
Real-trained bundle inference (192-dim, in-process, official seed 42): 1 flow 3.25 ms, 100 flows 7.7 ms, 1,000 flows 43.4 ms.

## 9. Honest gaps

- The default shipped model is trained on synthetic data; its 97.33 % must not be compared with the base paper. Real-data results are in section 4.2/4.3 and were produced in this documentation run (the shipped `models/` and `reports/` were left unchanged; the real-trained bundle is in `experiments/unsw_nb15/official/`).
- Not measured: RSA hybrid in the product (benchmark only), true network latency to a cloud provider, multi-user load, memory footprint, energy, adversarial/evasion robustness of the IDS, EECC of the base paper (not implemented), quantum NN of the base paper (not implemented; the project substitutes XGBoost + 1D CNN).
- Objective 1 (AES + RSA hybrid): met in spirit (hybrid asymmetric+symmetric) but with ECDH instead of RSA. Objective 5 (flag and log suspicious sessions): flows are scored and logged to an in-memory alert list; the product does not sniff live traffic or block transfers automatically.
