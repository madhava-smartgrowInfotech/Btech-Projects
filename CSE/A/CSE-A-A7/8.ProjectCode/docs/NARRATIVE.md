## One-paragraph story
Emergency staff must decide within minutes who is seen first; manual triage varies with the person on duty and under-identifies critical illness [Hinson]. Models built on structured fields cannot see what is written only in a scanned report. ATHENA reads a PDF or scanned report (text layer, or local RapidOCR for images), parses symptoms / findings / history / six lab values with a clinical lexicon that handles negation, fuses 28 report flags with 8 vitals into 36 inputs, and an isotonic-calibrated XGBoost gives priority 1 (Critical) to 5 (Non-urgent), a risk level and a calibrated confidence. Per-patient SHAP lists the strongest drivers. The clinician accepts or changes the priority (reason required), the override is stored, the queue reorders, a triage-summary PDF can be downloaded. It is decision support: the clinician decides.

## Honesty rules (these decide acceptance)
1. **All model numbers are on seeded synthetic data** (6,000 rows from 7 clinical archetypes plus a hand-written severity rule, noise sd 0.4). Say "on the synthetic hold-out" every time. Accuracy 69.4 % measures recovery of a known rule, not agreement with clinicians. A noise ceiling of 86.25 % exists. Do not call anything "clinically validated".
2. The batch objectives named BioBERT, PaddleOCR, multi-agent orchestration, RAG, MongoDB, Node + Flask, LIME and six disease-risk models. **Built instead:** a rule-based lexicon, RapidOCR (PaddleOCR-family models on ONNX Runtime), FastAPI + React, SQLite, SHAP. RAG, multi-agent orchestration, BioBERT, LIME, MongoDB and the six disease models were **not built**: state them as not done / future work. Gemini was dropped by choice (offline, no key).
3. Objective-by-objective status: O1 OCR stage - met (RapidOCR, PDF text layer). O2 medical language model for extraction - **partly met**: lexicon, 100 % on 12 generated samples, 84.3 % recall on the 40-fragment stress set. O3 fused representation - met (36 inputs). O4 model assigns risk level and priority - met on synthetic labels. O5 explanation layer - met (per-patient SHAP). O6 accuracy against clinician-assigned priority and time per patient - **partly met**: accuracy against the synthetic recorded priority only; time per patient measured (HTTP medians in `F.LAT`).
4. Weak points to report, not hide: P1 recall 43.9 %; high-risk (P1/P2) recall 66.2 % at argmax (84.3 % if flagged when P1+P2 >= 0.4, not implemented); under-triage 21.3 %; logistic regression (72.4 %) beats the shipped XGBoost on this data because the labels come from an additive score; isotonic calibration helps only modestly (ECE 0.047 -> 0.041) and the 0.8-0.9 confidence bin is over-confident; the reader has known defects (see REPORT_FACTS section 5); security is demo-grade; no real scans beyond 4 generated PNGs; no user study.
5. Comparison with the base paper: **different task** (ICD-10 diagnosis, 87 classes, 19 algorithms, 1,655 real cases) versus **5-level triage priority on synthetic data**. Put them side by side only with this caveat. Genuine parallels: probability ranking (their TOP-3 vs our Top-2 accuracy 95.3 %), a high-confidence threshold (their 0.85 vs our 0.85 row: coverage 25.5 %, accuracy 87.6 %), comparison across several algorithms (they 19, we 8), SHAP, absent symptom = 0 with no imputation (ATHENA does the same: an unreported flag is 0), and robustness to incomplete input (our dropped-flag experiment). Never claim ATHENA "beats" the base paper.
6. Novelty (be modest): the contribution is the integrated pipeline and its honest evaluation, not a new algorithm. New against the base paper: scanned-report intake (OCR) fused with vitals, five-level triage target, calibrated confidence, per-patient explanation beside the decision, clinician override loop stored as feedback, measured processing time, modality ablation (fused 68.3 % vs vitals-only 40.6 % vs report-only 63.2 %), robustness to dropped report findings. Standard components: XGBoost, SHAP, isotonic calibration, FastAPI, React.
