## Terminology
- Product **BotGraph**. Parts: the **ML pipeline** (`ml/`: graph builder, models, training, clustering, evaluation), the **API** (FastAPI, port 8309), the **web app** (React, port 5309, "V4 Soft Pastel Calm" kit), the **moderator queue**.
- "Account" = node, "tie" = edge (undirected). **Fake** = the label (570 accounts: 420 botnet members in 8 botnets + 150 lone spammers). "Flagged" = score at or above the served threshold (548 accounts at 0.5).
- **Served model** = GraphSAGE (best validation F1 among the three graph models). "Baseline" = feature-only MLP, same features, no graph, same split and training budget.
- "Real" parts: topology (3,963 accounts, 88,156 ties from SNAP Facebook circles), profile rows (Instagram labelled set), posting rows (Twitter bot set). "Synthetic" parts: 8 injected botnets, 150 lone spammers (6,300 injected ties), timing and interaction features, handles. Never write "real botnets" or "real-world accuracy" - say "injected, seeded botnets".
- Headline metric is **F1** (and precision/recall), not accuracy: fake accounts are 12.6 % of the data, so a classifier that says "genuine" for everything scores 87.4 % accuracy.
- Do NOT claim: Prufer/MST features (not implemented), text/linguistic/NLP features (not implemented, although the batch abstract mentions behavioural NLP), temporal/dynamic graphs, live platform ingestion, GPU training, reinforcement-guided augmentation, spectral filters.

## Base paper
PruferNET (Saha, Sarkar, Pratihar, IEEE Access vol. 14, 2026, DOI 10.1109/ACCESS.2026.3695637). It classifies nodes of the SNAP Facebook graph (4,039 nodes / 88,234 edges) into three depth classes of a minimum spanning tree with GraphSAGE (64 hidden, dropout 0.5, AdamW 0.003, 300 epochs, 60/20/20), adding Prufer-sequence features (frequency, entropy, unique ratio, transition influence, subtree depth) to degree/closeness/PageRank/trust; reports 99.63 % vs 96.54 % test accuracy; also Email-Eu-core. **It is an influence task: no fake labels, no bots, no clusters, no moderator loop, no scalability study.**
What BotGraph takes from it: the same family of data (SNAP Facebook ego networks), GraphSAGE as the backbone idea, 60/20/20 split, structure-plus-attributes features, and the argument that graph structure adds information a per-node model lacks.
What BotGraph does differently: supervised **bot/fake detection** with class imbalance; head-to-head GCN/GAT/GraphSAGE vs a no-graph baseline; **botnet cluster detection** from embeddings; **moderator queue with retraining that leaves the test split untouched**; **scalability sweep**; explanation of each score. The Prufer features are named as future work.
Never compare 99.63 % with BotGraph's numbers as if they measured the same thing; state the tasks, labels and data differ. Companion references: RABot (arXiv 2602.21749: reinforcement-guided augmentation for imbalanced, noisy bot detection) and HW-GNN (arXiv 2511.22493: homophily-aware spectral network for bot detection) - cited as related work and as the source of the imbalance/noise framing, not reproduced or compared numerically.

## The seven messages
1. **What was built:** an end-to-end system, not a notebook: graph builder with 23 features, four models on one stratified 60/20/20 split (2,719/906/908), Louvain botnet clustering, FastAPI backend with JWT roles and SQLite, React moderator app, 36-check smoke test, scalability sweep.
2. **The graph earns its place, but not every architecture does:** on the 908-account test split (114 fake), mean of 3 seeds - baseline F1 0.827; GCN 0.837 (+1.0 point, precision 0.958 but recall 0.743 *below* the baseline's 0.789); GAT 0.900 (+7.3); **GraphSAGE 0.939 (+11.2; precision 0.975, recall 0.906, ROC-AUC 0.990, PR-AUC 0.974)**. GraphSAGE's seed 0 confusion matrix: 3 false positives, 9 false negatives out of 908. GAT has the largest seed variance (F1 0.877-0.922) and costs 3-5x the time of GraphSAGE. Interpretation (stated as an explanation, not proven): GraphSAGE keeps the account's own features in a separate weight from the neighbourhood mean, which suits accounts whose profile is camouflaged but whose neighbourhood is not; GCN's symmetric-normalised smoothing mixes the account into hubs.
3. **Botnet clusters:** Louvain over the embedding-kNN + real-tie graph of every account scored at 0.30 or more finds 9 groups: all 8 injected botnets recovered as single communities (mean recall 1.000, mean precision 0.988, lowest precision 0.923), plus one loose group of 160 lone spammers/look-alikes with density 0.0014 (labelled "diffuse"). This is a known-answer test on seeded botnets with dense internal ties (each pair tied with p = 0.28) - it shows the method finds this kind of coordination; it does not show real-world botnet recall.
4. **Scale:** disjoint copies of the graph, CPU, 10 timed epochs: from 4,533 accounts / 94,456 ties to 36,264 accounts / 755,648 ties, GraphSAGE epoch 0.060 s -> 0.392 s (6.5x for 8x the size), inference 0.027 -> 0.186 s; GAT 0.255 -> 2.022 s; roughly linear in ties. The largest graph is far below platform scale (millions of accounts), and disjoint copies understate the cost of a real, well-mixed graph; the scale claim is limited to what was measured.
5. **Honest data caveats:** botnets and half of the features are synthetic; profile rows and posting rows come from different sources and are combined by resampling (no real cross-correlation); the Twitter bot label carries almost no signal so posting columns act as realistic noise; 40 % of bots (198 accounts) are given a genuine-looking profile and 231 genuine accounts a fake-looking one by design, otherwise the profile alone solves the task. High numbers therefore describe this benchmark, not Indian platforms (ShareChat, Moj) in the wild.
6. **Moderator loop:** confirm/dismiss on an account or a whole cluster is logged (SQLite `reviews`), used as training labels at the next retrain (reviewed accounts join training, test split never touched), F1 before/after recorded in `training_runs`; used decisions cannot be undone; analysts are read-only (403).
7. **Engineering evidence:** 36/36 smoke-test checks pass (auth, roles, graph counts, 3 models beat baseline, scalability, ranking, explanations, neighbourhood, clusters, moderator rules, retraining and its bookkeeping); API medians 3-16 ms (p95 <= 28 ms) on a shared i5-12500; login 233 ms (bcrypt); start-up 5.1 s. There is no pytest suite and no load or adversarial testing.

## Extra experiments (scripts/run_extra_experiments.py -> experiments/extra/metrics.json, numbers in docs/REPORT_FACTS.md section 13, `facts.EXTRA`)
8. **What the extra experiments show - this is an essential, honest part of the story:**
   - *Threshold:* GraphSAGE F1 stays 0.927-0.952 for every threshold from 0.30 to 0.60 (served 0.5: 0.946 on seed 0, 3 FP / 9 FN); the baseline peaks at 0.834 and cannot reach recall 0.9 without precision below 0.62. The result does not hinge on the tuned threshold.
   - *Error analysis:* GraphSAGE caught all 82 botnet members in the test split (baseline 64) but only 23 of 32 lone spammers (baseline 26). All 9 missed fakes are lone spammers with 4-8 ties. The graph helps against coordination and does not help against isolated accounts.
   - *Ablation:* the synthetic temporal group is the most valuable attribute group (GraphSAGE 0.942 -> 0.840 without it; baseline 0.822 -> 0.515); posting behaviour adds nothing; **GraphSAGE on node degree alone reaches F1 0.965, higher than with all 23 features (0.942)**. The injected structure is distinctive enough that structure alone nearly solves the benchmark. Therefore: the headline F1 shows the pipeline works and that neighbourhood information is decisive on this benchmark; it is NOT evidence of real-platform accuracy. Say this in the results, the conclusion, the limitations and the paper.
   - The ablation retrains in memory; its "all 23 features" row (0.822 / 0.942) differs from the main table (0.827 / 0.939) in the third decimal - say so where both appear.


## Honest limitations (use consistently)
Injected, seeded botnets; synthetic timing/interaction features; resampled (not paired) profile and posting rows; no text features; static snapshot graph (no time evolution); 4.5k-account benchmark, scalability measured only to 36k accounts on CPU with disjoint copies; three seeds and one split (no cross-validation, no confidence intervals beyond the std over 3 seeds); GAT non-deterministic (+-0.01); gradient x input explanations are a first-order approximation; threshold tuned on validation (0.5 for GraphSAGE); the base paper's numbers cannot be compared; no adversarial robustness testing; no pytest suite, no load test; timings on a shared i5-12500 (upper bounds); demo authentication only (JWT, two seeded users, no password reset or MFA, no rate limiting); no live platform data; `.venv` is created by setup.bat (not shipped).
