## 2. Two datasets - read this before quoting any number
1. **Shipped app = synthetic fallback.** `data/raw/SYNTHETIC_FALLBACK.txt`, `models/metadata.json: synthetic_fallback=true`. 1,400 generated rows (595 SUCCESS / 805 FAILURE), schema identical to the Kaggle table plus a text `description` built from templates (success templates and failure templates differ -> the text channel leaks the label by construction). All numbers in section 3 are on this data.
2. **Real public table.** "Startup Success Prediction" (Kaggle, manishkc06; listed CC0), 923 rows x 49 columns (US start-ups, acquired = success 597, closed = failure 326). The Kaggle download needs a login, so the identical 923-row CSV was fetched from a public GitHub copy (`sumitjhaleriya/Startup-Success-Prediction-using-Machine-Learning`) into `data/real/startup_data.csv` (not in `data/raw/`, so the app is unaffected). After the app's own de-duplication: **922 rows, 596 success (64.6 %) / 326 failure**. It has **no free-text description**, so the text/retrieval channel cannot be evaluated on it. Note "success" (acquired) is the MAJORITY class here, not the rare class the batch objectives assume.
- Real-data features: 9 numeric (age_first/last_funding_year, age_first/last_milestone_year, relationships, funding_rounds, funding_total_usd, milestones, avg_participants) + log funding; 7 binary (has_VC, has_angel, has_roundA-D, is_top500); state (top 10 + Other) and industry_type (Kaggle category_code mapped to the app's 10-name vocabulary, else Other). 37-38 encoded features.
- Known leakage-like fields: age_last_milestone_year, milestones, relationships are recorded after the outcome window in part; the Kaggle table gives no time stamps to remove them. Stated as a limitation.

## 6. Architecture summary
FastAPI backend (`app/main.py`, `app/api_extra.py`) -> services (`store.py` loads artefacts, trains on first run if missing; `predictor.py`; `insights.py`) -> ML (`dataset.py` Kaggle-or-synthetic loader, `preprocessing.py` impute/scale/one-hot, `embeddings.py` all-MiniLM-L6-v2 384-d, `retrieval.py` fusion + balanced cosine top-k, `models.py` four classifiers, `evaluation.py` 5 x 80/20 study + charts). Artefacts in `models/` (best_model.joblib, preprocessor.joblib, train_fused.npz, text_embeddings.npz, train_frame.pkl, metadata.json, evaluation_results.json). No database: state is files + in-memory `STATE`. React UI in `frontend/` (Landing, Login, Dashboard, Analyze, Performance, Insights) with Vite proxy to 8410; the original Jinja pages still work.
- Fusion: x = [alpha*s, (1-alpha)*t], alpha 0.5, s = L2-normalised structured vector (37-d), t = L2-normalised MiniLM embedding (384-d), final L2 normalisation, so cosine similarity = dot product.
- Retrieval: cosine similarity against TRAINING rows only, half/half success/failure quota (k = 10/20/30/50, default 50), weighted vote = sum(sim * label)/sum(sim).
- Models: Logistic Regression (lbfgs, balanced, C=1), Decision Tree (depth 8, min split 10, min leaf 5, balanced), Random Forest (300 trees, leaf 2, balanced), XGBoost (400 trees, depth 6, lr 0.05, subsample 0.8, colsample 0.8). Selection by balanced accuracy.
- Explanation: top-5 |coef| (LR) or importance (trees) with signed contribution, plus retrieval statistics. Risk label: "Lower risk" if SUCCESS and confidence >= 0.70, "Moderate risk" if confidence >= 0.55, else "Higher uncertainty".
- Target mapping: acquired/IPO -> SUCCESS(1), closed -> FAILURE(0). Input hygiene: dedup, numeric coercion, median/most-frequent imputation, log1p funding, description cleaning (company-name masking).

## 8. Objectives vs outcome (batch objectives 1-6)
1. Collect a dataset: partly - the real 923-row public table was obtained and analysed; the shipped app runs on the synthetic fallback with the same schema. Founder-experience and market-trend fields mentioned in the abstract are NOT in either dataset.
2. Clean + engineer features (funding velocity, team experience, market context): cleaning and log-funding done; "funding velocity" is only approximated by age_first/last_funding_year and rounds; no team-experience feature exists.
3. Class imbalance: handled with balanced class weights (app) and compared with oversampling on real data (4d); on real data failure is the minority.
4. Train and compare LR / DT / RF / boosting: done (plus HistGradientBoosting on real data).
5. Features that separate success from failure: done (4h, plus app feature-importance page).
6. Accuracy, precision, recall, F1, ROC-AUC: all measured in the real-data experiments; the shipped app's own evaluation reports balanced accuracy, accuracy, precision, recall, F1 (ROC-AUC for its fused model not recorded).

## 9. Honest gaps
- The shipped model's headline numbers (LR 0.749 balanced accuracy) come from synthetic data and must not be read as real-world performance.
- Real data has no text, so the novelty claim "text embeddings + retrieval help" is supported only on synthetic data where the text leaks the label; on real data it is untested.
- No temporal split (the Kaggle table has no usable dates) -> look-ahead bias cannot be excluded (the base paper itself cites this problem).
- 922 rows, single dataset, US only, one random seed family: confidence intervals are the ± std over 5 splits and are optimistic for the small test folds (185 rows).
- Base-paper numbers (85-92 %) cannot be compared like-for-like: the paper gives no dataset or table.

## 14. Position against the base papers
- Declared base paper [1] (IJRASET, Panjwani et al.): ensembles (RF, GB) best, 85-92 % accuracy, 70:30 split, ADASYN, Flask. No dataset size or per-model table. Here (real 922-row table, 70:30 x 5 seeds): RF accuracy 0.796 ± 0.013, HistGB 0.786, LR 0.729 - the ensemble ranking is reproduced, the 85-92 % level is NOT reached; under 5 x 80/20 the best accuracy is 0.775 (XGBoost).
- Method anchor [2] (Maarouf, Bakiaj, Feuerriegel, arXiv 2601.16568): 4,034 Crunchbase startups (35.15 % success), same 5 x 80/20 protocol, kNN-ICL balanced accuracy 0.713 (F1 0.632) at k=50, LR 0.631, RF 0.634, XGBoost 0.618, fused LLM (20,172 startups) 0.743. VenturePulse takes the retrieval-of-comparable-startups idea and the protocol, but replaces the LLM by a classifier plus retrieved evidence and runs locally. Datasets differ (their descriptions are text, ours real table has none), so numbers are not comparable.
- Reference paper [3] (Mashhadi et al., arXiv 2510.09465): Crunchbase firm-quarter panel 2010-2023, temporal splits; exit AUROC 0.872 (RF, inverse weights), funding 0.817, patents 0.921; PR-AUC primary. Here best real ROC-AUC 0.816 (RF) without temporal split.
