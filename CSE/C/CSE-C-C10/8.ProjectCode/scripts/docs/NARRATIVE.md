## What the project is
- Product **VenturePulse**: FastAPI backend (`app/main.py`, `app/api_extra.py`) + React/Vite frontend (`frontend/`, ports 8410 / 5410) + the original Jinja pages. Batch C10 (CSE-C), 4 students, guide P Prasanna. College, HOD, principal, year, designation stay bracketed placeholders from `facts.py`.
- Task: predict whether an early-stage startup ends as SUCCESS (acquired / IPO) or FAILURE (closed). Inputs: 9 numeric fields (funding_total_usd, funding_rounds, age_first/last_funding_year, age_first/last_milestone_year, relationships, milestones, avg_participants) + 7 flags (has_VC, has_angel, has_roundA-D, is_top500) + state + industry_type + optional free-text description (<= 2,000 characters) + k in {10,20,30,50}.
- Pipeline: dedup, target map -> median / most-frequent imputation, StandardScaler, one-hot, log1p funding (37 structured features) -> all-MiniLM-L6-v2 384-d embedding of the description (company name masked) -> fused vector [0.5 s, 0.5 t] L2-normalised -> best model (Logistic Regression, chosen by balanced accuracy over 5 x 80/20 stratified splits) gives P(success); in parallel a balanced top-k cosine retrieval (half success / half failure, TRAINING rows only) returns comparable startups; deterministic explanation = top-5 signed coefficient / importance terms + retrieval statistics; risk label (Lower risk / Moderate risk / Higher uncertainty). Models compared: Logistic Regression, Decision Tree, Random Forest, XGBoost (+ HistGradientBoosting in the real-data study).
- No SQL database: state = artefact files in `models/` + in-memory `STATE`; ER diagram shows the file-based data model. Demo sign-in (HMAC token) only protects the React screens, not a multi-user system.

## The honest story (state it plainly and consistently everywhere)
1. The system is built and works end to end: 7 pytest tests, 15 smoke checks, 29 API edge cases (51 checks, all pass); POST /predict median 148 ms (k=10) / 199 ms (k=50), GET endpoints 3-15 ms (127.0.0.1, CPU).
2. Two datasets, never mixed up. (a) The **shipped app** runs on a 1,400-row **synthetic fallback** (595 success / 805 failure; same schema as the public table plus template-generated descriptions whose wording differs between classes, so the text channel leaks the label). Its 0.749 balanced accuracy (LR) is a pipeline check, not evidence of real-world skill. (b) The **real public table** (Kaggle "Startup Success Prediction", 922 rows after dedup, 596 success / 326 failure, US only, structured columns only, NO text) is used for all real measurements via `scripts/run_experiments.py`. The screenshots show the app serving the synthetic-trained model with a real submission; say so in captions.
3. Real results (5 x 80/20 splits, structured features): Random Forest and XGBoost best, balanced accuracy 0.746, ROC-AUC 0.816 / 0.806, accuracy 0.773-0.775, F1 about 0.83; Logistic Regression 0.709 / 0.789; Decision Tree 0.703 / 0.742; HistGradientBoosting 0.727 / 0.806. RF, XGBoost and HGB are within one standard deviation of each other. The base paper's ensemble ranking is reproduced; its 85-92 % accuracy level is NOT (best 0.775 on 80/20; RF 0.796 on its 70:30 protocol); its dataset is unspecified so the comparison is qualitative.
4. Leakage-like fields: dropping relationships, milestones and the two milestone-age fields lowers ROC-AUC from about 0.82 to 0.72 (RF) and 0.70 (XGBoost) and removes the ensembles' lead over LR. Real numbers are therefore an upper bound for genuinely early-stage prediction; no temporal split is possible (no dates).
5. Imbalance: in the real table SUCCESS is the majority (64.6 %), the reverse of what the batch objectives assumed. Class weights / oversampling did not improve ROC-AUC; they trade recall of the success class for precision. Threshold sweep (LR): balanced accuracy is flat (0.71) between thresholds 0.30 and 0.50; recall of success falls from 0.88 to 0.67.
6. Retrieval: a retrieval-only classifier (balanced top-k cosine vote, no training) reaches balanced accuracy 0.70-0.71 and ROC-AUC 0.77-0.79 on real structured features, equal to LR and below RF/XGBoost; k matters little on real data. The text half of the fusion is untested on real data (the table has no descriptions); on synthetic data text-only 0.599 vs structured-only 0.714 vs combined 0.749, but the synthetic text leaks the label so this must not be sold as evidence that text helps in reality.
7. Calibration of LR on the real data: see REPORT_FACTS `calibration_logreg` (use `F.R['calibration_logreg']`); the UI "confidence" is max(P) and is not a guarantee. Feature drivers (real data): relationships first in both RF Gini (0.162) and permutation importance; milestones, age of last milestone, funding amount and age at first funding next; LR weights are dominated by state / top-500 / industry dummies, so coefficient ranking and tree ranking disagree - report both.
8. Objectives vs outcome: see REPORT_FACTS section 8 (1 partial, 2 partial, 3 done, 4 done, 5 done, 6 done with the ROC-AUC caveat for the shipped fused model). Founder experience, team size and market-trend data from the abstract do not exist in either dataset.
9. Novelty/contributions (honest, modest): (i) an end-to-end startup-outcome application that returns a prediction AND the comparable historical startups AND the feature drivers, with a React front end and local-only inference; (ii) fused structured + text representation with balanced, train-only cosine retrieval (leakage-safe; company names masked) adapted from the retrieval idea of [2] without an LLM; (iii) a reproducible benchmark on the real table with ten studies (models, imbalance, threshold, calibration, RF size, 70:30 protocol, synthetic-to-real transfer, leakage ablation, retrieval-only, per-industry); (iv) findings: ensembles > LR reproduced, 85-92 % not reproduced, leakage-like fields inflate AUC by about 0.1, retrieval alone equals LR, synthetic text leaks. Do not claim improvements the data do not show.
