## 9. Architecture

- Python 3.11 / Flask 3.1 / scikit-learn 1.9 (model pickled with 1.9.0, loaded with 1.9.1: warning only) / pandas / psutil / Scapy 2.8 / SQLite; React 19 + Vite 8 + Tailwind 4 + Recharts front end (about 3,100 lines of JSX/JS).
- Modules: `app.py` (389 lines), `ml/` (features, preprocessing, train_model, evaluate_model, model_loader), `monitoring/` (interface_manager, packet_capture, simulator, traffic_aggregator), `security/` (detector, distributed_analysis, severity, mitigation), `database/db.py`, `config/config.py`.
- Four SQLite tables: detections (14 columns), mitigations (6), health_samples (8), settings (2); no foreign keys.
- Defaults: window 10 s (2-120 allowed), baseline 12 windows, quarantine 40 s (x2 for Critical; 5-3600 allowed), health sample every 5 s, top 3 sources quarantined.
- Distributed risk = 0.30 min(src/30,1) + 0.30 min(dst/15,1) + 0.25 min(rate/1500,1) + 0.15 baseline-deviation; levels Low < 0.4 <= Medium < 0.7 <= High.
- Severity score: +30 Attack (or 8 x confidence if Benign), +15/+8 for confidence >= 0.9 / 0.75, +20/+12/+5 for rate >= 3000/1200/400, +20/+10 for risk >= 0.7/0.4, +8 for >= 25 sources or >= 12 destinations, +10/+5 for persistence >= 3 / 2; Benign capped at 45; Critical >= 70, High >= 50, Medium >= 28.
- 12 JSON endpoints: GET status, health, interfaces, detections, detections/latest, mitigations, settings, model/metrics; POST settings, monitor/start, monitor/stop, demo/start, demo/stop; plus `/` (legacy dashboard) and `/static/results/<file>`.
- Demo login of the React app is a browser-side gate (demo@sentinelflow.com / Demo@1234, localStorage); the REST API has no authentication and binds to 127.0.0.1.
- Hardware used: Intel Core i5-12500 (6 cores / 12 threads), 15.7 GB RAM, Windows 11 Pro, no GPU, no Npcap installed (live capture not possible on this machine).

## 11. Known limitations and defects found while documenting (state these plainly)

1. The shipped model was trained on synthetic fallback data (CICIDS2017 was unreachable when the product was built); 99.71 % accuracy is on a held-out split of that synthetic data plus simulator windows.
2. On real CICIDS2017 DDoS flows the shipped model scores 71.8 % accuracy, 63.4 % recall and 17.2 % false-positive rate.
3. Retrained on real flows with the same 10 features and hyper-parameters, the RF reaches 99.94 % (5 seeds); the product's own training script would do this if the CSV were placed in data/raw/. The labels in CICIDS2017 are known to have flaws (Engelen et al.); random splits of flow data overlap in time.
4. Window length matters: the model was calibrated on 10 s windows; at 2 s and 5 s windows (the Simulation Mode default is 5 s, the screenshots were captured at 2 s) the RF label alone raises many false alarms; the severity layer removes most of them.
5. The landing page and Model page show the 99.71 % figure; the Model page carries a 'synthetic training data' warning, the landing page does not.
6. The OS firewall is never touched (`apply_os_firewall_block` is a stub returning applied: false): 'mitigation' is an application-level denylist inside SentinelFlow; no traffic is actually dropped.
7. Live capture needs Npcap and Administrator rights; it could not be tested end to end on this machine (the error path was tested).
8. The saved forest has n_jobs=-1, which makes single-window inference ~10x slower than n_jobs=1 for one row.
9. Not measured: real SDN deployment, throughput under real attack load, recovery time of a real service, carpet-bombing with real traffic (only the simulator's carpet style), multi-class detection, online learning.
10. `interface` setting is not length-validated; the REST API has no authentication (localhost-only by design).
