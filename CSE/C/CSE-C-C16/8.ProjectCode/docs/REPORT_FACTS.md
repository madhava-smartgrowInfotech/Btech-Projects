## 2. What was built (and what was not)

- Web platform: React 18 + Vite 8 + TypeScript 5.9 + Tailwind 4 SPA (12 page components, `frontend/src`, 5,647 lines of TS/TSX), FastAPI layer `backend/main.py` (437 lines, 16 routes) over the original Flask product `agrivision/` (app.py 398, disease_db.py 221, inference.py 177, train.py 103 lines), one SQLite file (`users`, `results`). Ports 8416 / 5416, demo login `demo@agrivision.ai` / `demo1234`.
- **Diagnosis engine in the product = colour/texture heuristic** (`agrivision/inference.py`): 256x256 resize, share of green / brown / yellow / dark / white pixels and global std, hand-set score per class, a hash-seeded jitter, confidence mapped into 0.62-0.99 (never low). `agrivision/models/` is empty so no trained network is loaded; the UI says 'Heuristic engine' on every result.
- Knowledge base: 38 classes (14 crops: apple, blueberry, cherry, corn, grape, orange, peach, bell pepper, potato, raspberry, soybean, squash, strawberry, tomato; 12 healthy, 26 diseased), 26 diseases with curated symptoms/treatment/prevention, severity: 12 high / 14 medium / 12 none; per disease 3 treatments (chemical, organic, cultural) + prevention + lifecycle + cost text in rupees. Kinds: fungal 19, healthy 12, viral 3, bacterial 3, pest 1.
- Multilingual: English / Hindi / Marathi **interface strings only** (44 keys in `frontend/src/lib/i18n.tsx`); disease and treatment text stays English.
- **Not implemented** although the abstract lists them: yield prediction, weather-based recommendations (OpenWeatherMap), fertiliser-dose recommender (only treatment text), voice interface, administrative dashboard, a CNN in the product, expert validation of the advice. The dashboard 'season alert' is a fixed sentence.

## 3. Dataset (PlantDoc, measured)

- Source: PlantDoc (Singh et al., CoDS-COMAD 2020), CC-BY-4.0, HF mirror `geraldmc/plantdoc-full`; local copy `datasets/plantdoc-images` (git-ignored, 445 MB). Web-scraped field photos, 13 crops.
- Local folder layout: **2,342 train + 236 test = 2,578 images, 28 class folders in train, 27 in test** (`Tomato_two_spotted_spider_mites_leaf` has 2 train images and no test image). Test macro scores are therefore over 27 classes. Largest test class Corn_leaf_blight 12 (5.1 %).
- Class sizes (train): 2 to 180 images per class (Corn_leaf_blight 180, Tomato_Septoria 140, Squash_Powdery 124; Tomato_leaf_mosaic_virus 44, Cherry 47, spider mites 2). 10 healthy folders (Apple, Bell pepper, Blueberry, Cherry, Peach, Raspberry, Soybean, Strawberry, Tomato, Grape): 90 healthy and 146 diseased test images (61.9 % diseased).
- All 28 PlantDoc folders map one-to-one onto the 38 canonical classes (`PLANTDOC_MAP`); 10 canonical classes have no PlantDoc images (Apple black rot, Cherry powdery mildew, Corn healthy, Grape esca, Grape leaf blight, Orange HLB, Peach bacterial spot, Potato healthy, Strawberry leaf scorch, Tomato target spot).
- Original paper's numbers for context (verified from arXiv 1911.10317): 2,598 images, 27 classes; VGG16 on uncropped PlantDoc 13.74-29.73 % depending on pre-training; on cropped leaves 44.5-70.5 % (VGG16, InceptionV3, InceptionResNetV2, 80/20 split, 100x100 px).

### 4.1 The engine the app ships (heuristic), 5 `PYTHONHASHSEED` values (0 = what run.bat uses)

| Setting | Top-1 | Top-3 | Crop correct | Healthy-vs-diseased | Macro-F1 | Share answered |
|---|---|---|---|---|---|---|
| Crop chosen (true crop as hint) | 9.1 ± 1.0 % | 34.9 ± 1.6 % | 67.8 ± 0.0 % | 35.1 ± 0.9 % | 0.090 ± 0.015 | 67.8 % |
| Crop left on 'general' | 1.3 ± 0.7 % | 4.2 ± 0.8 % | 12.2 ± 0.6 % | 33.1 ± 0.3 % | 0.014 ± 0.007 | 100 % |

- With hash seed 0 and the crop chosen: top-1 10.6 %, top-3 36.4 %, macro-F1 0.119. Among photos that got an answer: 13.4 ± 1.5 %.
- Chance: 36.0 % if the crop is known (average of 1/candidates), 2.6 % on 38 classes, majority class 5.1 %.
- **32.2 % of test photos get no answer when the crop is chosen**: crops with fewer than 3 candidate classes (blueberry, cherry, orange/citrus, peach, bell pepper, raspberry, soybean, squash, strawberry = 10 of the 19 crop options) raise `IndexError` in `_heuristic_predict` and the API returns HTTP 400 `UNREADABLE_IMAGE` for a valid photo.
- Healthy leaves recognised as healthy: 10.2 ± 0.8 % (crop chosen); diseased leaves called diseased: 50.4 ± 1.1 %. Healthy-vs-diseased accuracy 35.1 ± 0.9 % is below the 61.9 % obtained by always answering 'diseased'.
- Picture shown by the app (screenshots 08, 09, 10): the demo account holds 10 scans, 8 read 'healthy' at 97.2 %; five of those are PlantDoc photos of diseased leaves (tomato late blight, potato early blight, corn rust, grape black rot, apple scab), so the screens show the engine calling visibly lesioned leaves healthy.
- Reported confidence is not a probability: the three shown scores add up to more than 102 % on 82 % of the 160 test photos the heuristic can answer (max 112 %); mean shown confidence 95 %, yet top-1 is correct on only 21 %, 22 % and 14 % of photos in the 0.80-0.90, 0.90-0.95 and 0.95-1.00 bins; reported latency has a constant +40 ms added in `predict()`.

### 4.2 Compact CNN of `agrivision/train.py` (189,655 parameters, 2.4 MB .keras file), trained here

Protocol: 224 px, Adam 1e-3, batch 32, in-model augmentation (flip, rotation 0.08, zoom 0.1, contrast 0.1), 10 % stratified validation split carved from the train folder (the shipped script uses the test folder as validation), early stopping on validation accuracy (patience 8), ReduceLROnPlateau, up to 60 epochs, seeds 42/43/44.

| Run | Accuracy | Macro-F1 | Top-3 | Crop correct | Healthy-vs-diseased | Epochs | Train time |
|---|---|---|---|---|---|---|---|
| CNN, held-out validation (3 seeds) | 12.0 ± 0.5 % | 0.086 ± 0.010 | 30.9 ± 1.9 % | 26.0 ± 4.6 % | 76.8 ± 1.9 % | 28 | 478 s |
| CNN, shipped protocol (test folder as validation, seed 42) | 13.6 % | 0.090 | 26.7 % | 25.4 % | 78.0 % | 31 | 520 s |
| CNN, no LR decay, 100 epochs max, patience 20 (seed 42) | 12.7 % | 0.092 | 29.7 % | 23.7 % | 74.6 % | 39 | 656 s |

- Training accuracy only 22.2 ± 2.8 % and best validation accuracy 18.7 ± 2.0 %: the network under-fits (it does not memorise); more epochs or a smaller learning-rate decay did not change that (third row). It never reaches the 'PD36-C' level the docstring suggests ('~1.1M params' in `train.py`; measured 189,655).
- CPU inference, batch of 1: median 70 ms, p95 88 ms per image (TensorFlow `predict`, includes Python overhead).
- Best classes (seed 42): Tomato yellow-leaf-curl virus F1 0.67, Strawberry 0.38, Corn rust 0.27; many classes F1 = 0.

### 4.4 Comparison with the base papers (state plainly in the documents)

- Foliagen (base paper) generates foliage images and evaluates VGG19, ResNet50, DenseNet121, Swin and CBAM-ConvNeXt on soybean/tomato foliage; it reports up to 98 % accuracy when 5 % of a natural foliage set is added to generated data. No numbers are comparable: different task (image generation for training), crops (soybean, tomato), data (generated foliage + SHV UAV set), GPUs (2 x RTX 6000 Ada). This project did not implement Foliagen, foliage-level images or generated data.
- PD36-C: 99.53 % on the New Plant Diseases Dataset (augmented PlantVillage, laboratory backgrounds, 38 classes). Here: PlantDoc field photos, 28 classes, 2,342 training images: best 50.3 %. Data difficulty, size and class set differ; do not present as a like-for-like comparison.

## 10. Objectives against outcomes

1. Labelled dataset of healthy and diseased leaves: **achieved** (PlantDoc 2,578 images, 28 classes, 13 crops; web photos, not self-collected).
2. Preprocess and augment: **partly** (resize to 224 and in-model flip/rotation/zoom/contrast in `train.py`; the product's heuristic only resizes to 256).
3. Train a CNN for disease classes: **trained but not accurate** (11-13 % for the shipped recipe; MobileNetV2 transfer 50.3 %) and **not shipped in the product**.
4. Map disease to treatment and fertiliser advice: **treatment mapping achieved for all 38 classes; fertiliser, yield and weather advice not implemented; advice not validated by an agronomist**.
5. Web interface with multilingual support: **web interface achieved; multilingual only for interface strings (en/hi/mr)**.
6. Per-class accuracy and validation of recommendations: **per-class accuracy measured; recommendations not validated**.
