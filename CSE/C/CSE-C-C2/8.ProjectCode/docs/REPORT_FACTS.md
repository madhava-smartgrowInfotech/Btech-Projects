## 1. Project
- Product: **StoryVox** - Multilingual Story Generation and Speech System. Batch CSE-C-C2, API port 8402, web port 5402.
- Students: Lingala Sindhu (23K91A05D3), Padige Ajay (23K91A05H8), Mahek Ansari (23K91A05D8), Maheshwaram Hari Krishna (23K91A05D9). Guide: A Tejaswini.
- Base paper (from the batch documents): C. Tran and S. Sakti, *SAM Translator*, IEEE Access vol. 14, pp. 2742-2752, 2026, doi 10.1109/ACCESS.2025.3644647.
  mBART + self-paced learning + sparse mixture-of-experts (8 experts, top-2; 611M vs 1.7B parameters) + data-augmented self-training; BLEU on CVSS-C and CoVoST-2.
  **StoryVox implements none of these techniques**; it is a cascade of pretrained models. Numbers are not comparable (SAM: BLEU; StoryVox: TTS-to-ASR WER/CER and RTF).
- Supporting references: OmniVoice (arXiv 2604.00688: 646 languages, avg CER 4.00%, RTF 0.0319), MultiGen (arXiv 2508.08715).
  `archived_base_papers/BASEPAPER_REFERENCES.md` names OmniVoice as base paper - this conflicts with the batch documents; SAM Translator was used.

## 2. Architecture
- UI: React 19 + Vite, five pages (Landing, Studio, History, Story detail, Evaluation).
- API: FastAPI + Uvicorn, 11 routes + SPA fallback: GET /api/health, /api/languages, /api/meta, /api/stories, /api/stories/{id}, /api/audio/{id}, /api/evaluations;
  POST /api/stories/generate, /api/stories/{id}/synthesize, /api/evaluations/run; DELETE /api/stories/{id}.
- Storage: SQLite `data/storyvox.db` (tables stories, audio_outputs, evaluations); WAV in `data/audio/`; evaluation JSON/CSV in `data/evaluations/`.
- Story model: `Qwen/Qwen3-0.6B` (transformers text-generation pipeline, raw prompt, no chat template); max_new_tokens 220/420/700 for Short/Medium/Long; temperature 0.8, top_p 0.9;
  offline composer `storyvox-local-fallback-v1` when output < 20 words or the pipeline fails.
- Narration: `TTSProvider` ABC; `MMSTTSProvider` (VITS `facebook/mms-tts-*`, 16 kHz, 380-char chunks, peak-normalise 0.9, 0.25 s pause) then `SystemTTSProvider` (pyttsx3 / OS voice).
- Evaluation: Whisper-small ASR, multilingual MiniLM similarity (TF-IDF proxy if unavailable), jiwer WER/CER, ROUGE-L, RTF = synthesis time / audio duration.
- Configuration: 15 languages (en hi es fr de it pt ru ar tr nl pl zh ja ko), 8 styles, 3 lengths.

## 3. Honest gaps (objectives in the batch documents that the code does not implement)
- No translation module (the story is generated directly in the target language).
- No voice or speed selection (one fixed voice per language; `rate` only applies to the OS fallback).
- No user rating / coherence feedback collection.
- No reference-audio / voice cloning upload.
- Checkpoints `facebook/mms-tts-ita`, `-cmn`, `-jpn` do not exist on the Hugging Face Hub: Italian, Chinese and Japanese fall back to the OS voice (English David/Zira only on the test machine).
- `ffmpeg` is an undeclared dependency: without it Whisper cannot read the WAV and WER/CER are null (as in the evaluation JSON that shipped with the repo).
- Korean needs the `uroman` package, which `requirements.txt` does not list.
- The project `.venv` was created on another machine (points to a missing Python 3.14) and D: had ~1.5 GB free, so all runs used system Python 3.11.9 (torch 2.14.1, transformers 5.20.2).

## 4. Experimental setup
- Machine: Intel Core i5-12500 (12 logical threads), 15.7 GB RAM, CPU only (device = cpu), torch 2.14.1+cpu.
- Data: google/fleurs test split (CC BY 4.0), first 10 sentences per language within a length window.
- ASR: openai/whisper-small (load 6.56 s). TTS: app default chain (facebook/mms-tts-* then OS fallback).
- WER/CER reported two ways: *raw* (the app's own `wer()`; no normalisation) and *normalised* (NFKC, lower-case, punctuation removed; spaces removed for zh/ja). WER is not reported for zh/ja.
