## What the project is
- Product name **TruthGlow** (React web app) over a pure-Python library `src/` (PCA + Firefly + MSVM pipeline) and a FastAPI layer. Also kept: CLI and Streamlit app. Batch C6 (CSE-C), 4 students, guide K Rajasekhar Rao. College, HOD, principal, year, designation stay as the bracketed placeholders in `facts.py`.
- Pipeline: clean text -> TF-IDF (1-2 grams) + 25 stylometric features -> StandardScaler -> PCA (95 % variance target, cap 300) -> 80/20 split -> Firefly (mask over PCA components + C + gamma, fitness = 3-fold CV macro-F1 - 0.02 x selected share) -> RBF SVM (one-vs-rest shape, balanced class weights, probability=True). Three classes: REAL / PARTIALLY TRUE / FAKE.
- Two model artefacts exist and must never be confused: (a) the **shipped demo model** (`models/msvm_model.pkl`), trained on a synthetic template corpus (750 documents) - its 1.000 scores are a pipeline check, not evidence; (b) the **LIAR2 model** (`models/liar2_msvm_model.pkl`, seed 42) and the 3-seed LIAR2 experiments - the real results. The screenshots 10-22 show the app running the LIAR2 model; 01-09 show the demo model.

## The honest story (state it plainly and consistently everywhere)
1. The system is built and works end to end (6 screens, 8 API endpoints, 83 automated checks pass, ~4 ms server latency per article, 2,296 statements in ~1.2 s).
2. On real fact-checked statements (LIAR2, 3 classes, 3,000 training statements, 3 seeds) the proposed pipeline reaches macro-F1 ~0.43 and accuracy ~0.49 on the 2,296-statement test split. The task is hard: majority class gets accuracy 0.576 but macro-F1 0.244; the survey paper [2] finds LIAR-PLUS the hardest dataset for nearly all models even in the binary setting.
3. The optimiser did **not** produce a clear gain: PCA + default SVM, equal-budget random search and Firefly are within noise of each other on test; Firefly gave a slightly higher training-split fitness than random search. Simple TF-IDF linear models are better and ~1000x cheaper to train (logistic regression on all 18,369 statements: macro-F1 0.500). The objective "improve accuracy and computational complexity" is therefore **not achieved** on this data; what was achieved is a working, measured, reproducible system and an honest comparison. Say so in Results, Conclusion, Scope & Limitations.
4. PARTIALLY TRUE is the hardest class (F1 ~0.24); FAKE is the easiest (~0.63).
5. A confidence of 0.6-0.8 is more reliable than 0.4-0.5 (see `F.EA['by_confidence']`), but the verdict and the displayed probabilities disagree on ~49 % of statements (`F.LV`): the verdict is `SVC.predict`, the probabilities are Platt-scaled; the UI confidence is the max probability. Report as a finding/limitation, with the shipped screenshot 13 as the illustration.
6. Base paper (Saad et al. 2026): Arabic, binary, 7,474 articles, CAMeLBERT + NN + class weighting, accuracy 95.52 %, F1 96.19 %, Tesla T4. Compare only qualitatively and say plainly that data, language, task (binary vs 3-class) and compute differ so the numbers are not comparable. What this project takes from it: class weighting for imbalance, reporting several metrics, a comparison against baselines; what differs: classical features + PCA + metaheuristic instead of transformer embeddings, three classes, English, CPU only.
7. Novelty/contributions (honest, modest): (i) an end-to-end PCA + Firefly + MSVM pipeline with an explicit PARTIALLY TRUE class packaged as a usable web app with batch, analytics and retraining; (ii) joint Firefly search over component mask + C + gamma with a size penalty; (iii) a reproducible real-data benchmark on LIAR2 with equal-budget random-search, mask-only and linear baselines; (iv) findings: the optimiser's gain is within noise, PCA cap keeps only ~29 % of variance, label/probability disagreement. Do not claim improvements that the data does not show.
8. Gaps to state: stemming not implemented (objective 2 lists it); subsample of 3,000 training statements (compute); 3 seeds, no significance test; no ISOT; no user study; no load test; Firefly hyper-parameters untuned; UI wording assumes the demo model; `load_csv` true/false boolean issue; the four batch-survey papers [27]-[30] could not be verified.
