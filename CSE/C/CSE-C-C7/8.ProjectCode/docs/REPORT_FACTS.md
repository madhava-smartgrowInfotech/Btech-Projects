## 2. What the product is (verified in the code)

- FastAPI backend (`app/main.py`, `app/api_routes.py`) with SQLAlchemy 2 + SQLite (`learnpathiq.db`); original Jinja2 server-rendered UI on port 8407 plus a React 19 / Vite frontend (`frontend/`, port 5407) that proxies `/api` and `/static` to the backend.
- 6 tables: `users`, `profiles` (1:1), `courses` (24 seeded from `data/catalog/courses.json`), `interactions`, `recommendation_logs`, `auth_tokens`.
- Hybrid ranker `app/recommender.py::rank_courses`: score = 0.30 content (TF-IDF cosine, `max_features=2000`, English stop words, fitted on profile + 24 course texts per request) + 0.15 skill compatibility (|level difference| 0/1/2 -> 1.0/0.6/0.3) + 0.15 topic-interest overlap + 0.12 predicted success probability + 0.10 (0.5 + behavioural boost, clipped to [-0.3, 0.35]) + 0.08 goal match (0.7/0.4) + 0.05 normalised rating + 0.05 engagement score; clipped to [0,1].
- Behavioural weights: view .05, open .06, start .12, content .10, quiz .14, forum .10, save .08, complete .20, dismiss -.25 (x event value, per course).
- Engagement score = min(1, 0.25 + 0.04 x recent events + 0.03 x quizzes + 0.08 x completions); labels Getting started (<0.4) / Steady learner (<0.7) / Highly engaged; 'Needs a nudge' if a dismiss is among the last 5 events and score < 0.45.
- Success model input (8 features): cum_clicks, recent_clicks, quiz_count, forum_count, completions, engagement, weekly_hours, skill_code. Success model shipped = the validation-AUC winner (logistic regression).
- Action scoring: one-vs-rest T-learner (two logistic regressions per action: treated vs not-treated) over quiz / content / forum / homepage / continue_course; estimated benefit = P1 - P0; `best_action = argmax`. Described as 'estimated benefit', not a proven causal effect.
- Security: pbkdf2_sha256 (29,000 rounds) password hashes, `secrets.token_urlsafe(32)` tokens stored in `auth_tokens`, HttpOnly SameSite=Lax cookie `lpq_token` (72 h) or `X-Token` / Bearer header, Pydantic v2 validation (EmailStr, length limits), ORM parameterised queries.
- Pages (React): Landing, Login, Register, Catalog, Course detail, Dashboard, Recommendations, Learning path, Insights, Activity, Profile, Model analytics (4 tabs: Models / Diagnostics / Offline policy / Fairness audit).
- Code size: app/*.py = 649 lines; frontend pages and components about 3,360 lines of JSX; tests/test_app.py 5 tests.

## 4. Dataset (read this before quoting any model number)

- **Source: `synthetic-oulad-like-fallback-v1`** - a reproducible synthetic OULAD-like generator in `scripts/train_pipeline.py::acquire_data` (seed 42). The script probes the Open University Learning Analytics Dataset page but the real OULAD was NOT downloaded or used. OULAD itself (Kuzilek, Hlosta, Zdrahal 2017) is CC BY 4.0; the synthetic data carries no third-party licence.
- Size: 2,200 synthetic learners x 12 weeks = 26,400 learner-week rows; 8 observable features + hidden assessment score; success rate 44.0%; treatment-action counts {'quiz': 8424, 'content': 5292, 'continue_course': 5185, 'homepage': 5172, 'forum': 2327}.
- Split: learner-level 80/10/10 (seed 42): train 21,120 rows (1,760 learners), validation 2,640 (220), test 2,640 (220); positive rate on test 43.8%.
- Label: `success = (assess_score >= 50) AND (U < 0.55 + 0.2 (assess-50)/50)` with U uniform noise, i.e. noisy, and assess_score is NOT an observable feature of the deployed model.
- Correlation of each feature with success: cum_clicks 0.138, recent_clicks 0.183, quiz_count 0.054, forum_count 0.002, completions 0.058, engagement 0.182, weekly_hours 0.044, skill_code 0.099.
- Ceiling check: adding the hidden assessment score as a feature lifts test AUC to LR 0.8000 / RF 0.7858 / XGB 0.7868 (shipped features: 0.6028 / 0.5439 / 0.5994).
- Course catalog: 24 hand-written courses, 9 categories, levels 15 Beginner / 6 Intermediate / 2 All levels / 1 Advanced, rating 4.3-4.7, 4-30 h. No real learner-course interaction log exists; collaborative filtering over real learner histories is NOT implemented (the behavioural boost is per-learner, not cross-learner).

## 6. Offline policy evaluation (shipped run)

- Behaviour policy: multinomial logistic regression over the 5 actions; propensities clipped to [0.02, 0.98], importance weights capped at 10; target policy = argmax uplift per learner-week; rewards = observed success.
- IPS 0.0088, SNIPS 0.6652, Doubly Robust 0.4355; effective sample size 9.1 of 2,640 test rows. The huge gap between IPS (0.009) and SNIPS (0.665) and the ESS of about 9 mean the estimates are dominated by a handful of rows: NOT a reliable evidence of policy gain. Logged success rate on the test rows is 0.4375.
- Base paper for comparison (OULAD, different data and task): XGBoost AUC 0.795, Brier 0.074; logged pass rate 0.589; Greedy-Uplift SNIPS 0.619 [0.613, 0.625]; IPS 9.956 vs SNIPS 0.643 in its Table 4. Not comparable with this project (synthetic data, no RL agent).

## 9. Feedback loop and action-score behaviour

- Persona 'python, data science, machine learning' (Beginner): before any event top-3 ['ML101', 'DS101', 'DA101']; after 6 events (start/quiz/quiz/complete on ML101, view DS101, dismiss DA101) top-3 ['ML101', 'DS101', 'PY101']; ML101 score 0.4867 -> 0.5514; DA101 rank 3 -> 4; success estimate 0.202 -> 0.324; engagement Getting started -> Steady learner.
- Estimated action benefits flip sign with a few events: before {'quiz': 0.0912, 'content': 0.011, 'forum': 0.0084, 'homepage': -0.041, 'continue_course': -0.0046}, after {'quiz': -0.1798, 'content': 0.1088, 'forum': 0.122, 'homepage': 0.1629, 'continue_course': 0.1314}; best action quiz -> homepage. The uplift models extrapolate from a confounded, synthetic log.
- Grid of 45 learner states: best-action counts {'quiz': 9, 'content': 3, 'homepage': 7, 'continue_course': 23, 'forum': 3}; predicted success ranges 0.192-0.645 (mean 0.454). The suggested action depends on the learner state only, so every card in one learner's list shows the same suggested action (visible in screenshot 08).

## 14. Gaps stated plainly

- The real OULAD data was never used; every metric is from the synthetic OULAD-like generator. No external-validity claim is made.
- Test AUC is about 0.60 (selected model 0.6028; 6-seed mean 0.614 for logistic regression): modest discrimination, because the deployed features carry little signal about the synthetic label.
- Offline policy values (SNIPS 0.665, DR 0.436) rest on an effective sample size of 9.1 and are not evidence that the action policy improves outcomes.
- No live A/B test, no user study, no precision/recall against real learner feedback (objective 6 is only partly met: persona-based precision@k and MRR on a 24-course catalog).
- Collaborative filtering across learners (objective 3) is not implemented; the behavioural term is per learner. Learning paths are ordered by skill level then score, not by an explicit prerequisite graph.
- The base paper's Actor-Critic reinforcement-learning agent and causal regularisation are not implemented; the project borrows its uplift (T-learner) + OPE + fairness-audit components only.
- No cache, single-node SQLite, demo-grade token auth; the app is intended for local use.
