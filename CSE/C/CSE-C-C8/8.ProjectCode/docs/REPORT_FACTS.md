## 2. Architecture (from the code)

PDF -> PyMuPDF extraction (`pdf_extract`) -> features (`features`) -> decision signal (`ml_predict`) -> review (`review_synthesis`, local Qwen2.5-1.5B via `llm_service`) -> OpenAlex literature (`literature`) -> reviewer matching (`matching`, `embeddings`) -> SQLite `analyses` -> JSON/PDF export (`export_service`).
Match score = 0.55 expertise + 0.20 keyword + 0.15 method/topic + 0.10 availability - 0.60 conflict penalty (x100, clipped 0-100); bands Strong>=65, Good>=45, Possible>=25, Weak.
Endpoints: GET /api/health; GET /api/model/metrics; GET,POST /api/reviewers; PUT,DELETE /api/reviewers/{id}; GET /api/reviewers/export/csv; POST /api/reviewers/import; POST /api/analyze; GET /api/analyses; GET /api/analyses/{id}; GET /api/analyses/{id}/export?format=json|pdf.

## 9. Defects found while measuring (documented, not fixed in this run)

- OpenAlex returns HTTP 400 when the extracted title contains a question mark (`?`): the survey PDF's title gives `literature_retrieval_status = unavailable`; the query string is not sanitised.
- Section detection does not recognise roman-numeral headings (`I. INTRODUCTION`); the IEEE base paper PDF reports no introduction and its title heuristic returns the DOI line.
- The coverage chart's Novelty value is a fixed 55; novelty is not measured.
- Analysis timestamps are stored as naive UTC (`datetime.utcnow`) and shown by the UI without a zone, so they read about 5.5 hours behind local time (IST).
- A corrupt PDF that still starts with `%PDF` returns HTTP 200 with almost no extracted text (and the short-text warning); a reviewer CSV without display names imports 0 rows without an error.
- The TF-IDF fallback vocabulary is fitted once on the first request and then frozen.
- Conflict detection is literal string matching: paraphrased affiliations and first-name-only mentions are missed.
